# ADR 0004: React Native (Expo) for mobile instead of Flutter

- **Status:** Accepted
- **Date:** 2026-11-08
- **Supersedes:** the Flutter choice in the original brief and in ADR 0003

## Context

The original brief named Flutter for the resident mobile app. The product owner decided the
mobile app should use React. The rest of the stack is TypeScript and React (Next.js, NestJS).

## Decision

Build **VEYRA Resident** (`apps/resident-mobile`) with **React Native + Expo** (Expo Router,
EAS Build/Submit, over-the-air updates through EAS Update).

## Consequences

- One language (TypeScript) across backend, web and mobile. Shared packages
  (`@veyra/domain`, `@veyra/api-contracts`, `@veyra/design-tokens`) are used directly by the
  mobile app instead of being duplicated in Dart.
- Web developers can contribute to mobile with less ramp-up.
- The mobile app lives in the Bun workspace. `bunfig.toml` uses the hoisted linker because
  Metro expects a flat `node_modules`.
- Native folders (`ios/`, `android/`) are generated by `expo prebuild` and not committed
  (Continuous Native Generation). Native modules beyond the Expo SDK need a development build
  rather than Expo Go.
- Testing: Vitest for non-UI logic in `src/lib`; component tests (jest-expo + React Native
  Testing Library) and device E2E (Maestro) are added when real screens exist.
- Store builds need Apple Developer and Google Play accounts and EAS credentials.
